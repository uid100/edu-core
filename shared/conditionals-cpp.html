Overview

Conditional statements in C++ let your program make decisions.

    The most common forms are:
  • if
  • if / else
  • if / else if / else

  • if checks a condition and runs code if it’s true.
  • else provides an alternate path when the if condition is false.
  • else if lets you chain multiple conditions in a clear, mutually exclusive way.

    You can also combine conditions with logical operators
  • && (AND),
  • || (OR),
  • ! (NOT),
    • ... and occasionally nest conditions for more complex logic.

if

Use if when you want to execute code only if a condition is true. 

// Example: Alert if temperature exceeds threshold
  #include <iostream>
  int main() {
    int temperature = 78;
    int threshold   = 75;

    if (temperature > threshold) {
        std::cout << "Warning: Hot!\n";
    }

    // Code continues regardless...
    std::cout << "Done.\n";
  }
  • Condition expressions evaluate to true (non-zero) or false (zero).
  • Always use braces { } for clarity, even for single statements.
if / else

else runs when the if condition is false—ensuring exactly one branch executes. 

// Example: Even / Odd
  #include <iostream>
  int main() {
    int n = 42;

    if (n % 2 == 0) {
        std::cout << n << " is even\n";
    } else {
        std::cout << n << " is odd\n";
    }
  }

Tip: Prefer clear branching over cleverness. A ternary operator (cond ? a : b) is fine for short expressions but don’t overuse it.

if / else if / else

Chain mutually exclusive conditions with else if, finishing with an optional else for “none of the above.” 

// Example: Letter grade
  #include <iostream>
  int main() {
    int score = 86;

    if (score >= 90) {
        std::cout << "A\n";
    } else if (score >= 80) {
        std::cout << "B\n";
    } else if (score >= 70) {
        std::cout << "C\n";
    } else if (score >= 60) {
        std::cout << "D\n";
    } else {
        std::cout << "F\n";
    }
  }
  • Order matters: once one condition is true, the rest are skipped.
  • Use else if (not separate if statements) when cases are mutually exclusive.
Logical Operators & Short-Circuiting

Logical operators combine conditions:

  • && (AND): true only if both operands are true. Short-circuits—if the left is false, the right is not evaluated.
  • || (OR): true if at least one operand is true. Short-circuits—if the left is true, the right is not evaluated.
  • ! (NOT): inverts a boolean.
// Example: Safe checks with short-circuiting
  #include <iostream>
  #include <vector>
  bool expensiveTest() {
    std::cout << "[expensiveTest]\n";
    // Imagine slow I/O or complex math here...
    return true;
  }
  int main() {
    std::vector<int> data {1, 2, 3};

    // Using &&: cheap check first prevents out-of-range access
    if (!data.empty() && data[0] == 1) {
        std::cout << "First element is 1\n";
    }

    // Using ||: if left is true, right is skipped
    bool ready = true;
    if (ready || expensiveTest()) {
        std::cout << "Proceed (expensiveTest skipped if ready==true)\n";
    }
  }

Best practice: Put cheap (and safety) checks on the left so short-circuiting can skip expensive or unsafe work.

Nested if

Nesting lets you express a decision tree: decide broadly, then refine inside. Keep nesting shallow for readability.

// Example: Role-based action with validation
  #include <iostream>
  #include <string>
  int main() {
    std::string role = "admin";
    bool authenticated = true;

    if (authenticated) {
        if (role == "admin") {
            std::cout << "Admin panel\n";
        } else if (role == "editor") {
            std::cout << "Editor workspace\n";
        } else {
            std::cout << "Viewer dashboard\n";
        }
    } else {
        std::cout << "Please sign in.\n";
    }
  }

Consider refactoring deeply nested chains into functions, early returns, or switch (for integral/enumeration keys) to improve clarity.

Common Patterns & Pitfalls
1) The “dangling else” — always use braces
// Ambiguous without braces:
  if (x > 0)
    if (x > 10)
      std::cout << "big\n";
    else
      std::cout << "non-positive?\n"; // else binds to inner if (not outer)

  // Clear with braces:
  if (x > 0) {
    if (x > 10) {
        std::cout << "big\n";
    } else {
      std::cout << "small positive\n";
    }
  } else {
    std::cout << "non-positive\n";
  }
2) Assignment vs equality
// Common bug: using = instead of ==
  bool flag = false;
  if (flag = true) {           // assigns true; condition always true
    // ...
  }

  // Correct:
  if (flag == true) { /* ... */ }

  // or simply:
  if (flag) { /* ... */ }
3) Floating-point comparisons
#include <cmath>

  double a = 0.1 * 3.0; // might not be exactly 0.3 due to FP representation
  double b = 0.3;
  const double eps = 1e-9;
  if (std::abs(a - b) < eps) {
    // treat as equal
  }
4) Prefer early returns to reduce nesting
// Instead of deeply nested ifs:
  bool validate(User* u) {
    if (u != nullptr) {
        if (u->active) {
            if (u->age >= 18) {
                return true;
            }
        }
    }
    return false;
  }

  // Use guards and early returns:
  bool validate(User* u) {
    if (u == nullptr) return false;
    if (!u->active) return false;
    if (u->age < 18) return false;
    return true;
  }
Quick Practice
  1. Write an if/else that prints “leap year” if a year is divisible by 400, or divisible by 4 but not by 100; otherwise “not leap year”.
  2. Given an input character, print “digit”, “letter”, or “other”. (Use an else if chain.)
  3. Combine checks: if a vector is non-empty and its last element is even, print it. Ensure you don't access out of range.
  4. Refactor a 5-branch else if ladder into a switch if the key is an enum class.
Sidebar: Prioritize Conditions for Efficiency

When ordering an if ladder or a compound condition, evaluate from least complex & most selective to most complex so you can exit early (via short-circuiting) and avoid expensive work.

  1. Safety first: Guard against invalid states (e.g., null pointers, empty containers, index bounds).
  2. Cheap checks next: Booleans, flags, simple integer/range comparisons.
  3. Moderate checks: Small string compares, small set membership.
  4. Expensive checks last: I/O, regex, heavy computation, database calls.
// Good: safe & cheap before expensive
  if (ptr != nullptr && ptr->ready && isSmallCase() && heavyCompute()) {
  // ...
  }

  // Edge-case short-circuit examples
  if (!vec.empty() && vec.back() % 2 == 0) { /* safe & quick */ }

  bool cacheHit = hasCacheKey(k);
  if (cacheHit || fetchFromNetwork(k)) { /* avoid network if possible */ }

  // Ordering in else-if ladder (mutually exclusive):
  if (error) { /* quickest exit */ }
  else if (warning) { /* less likely but simple */ }
  else if (needsRebuild()) { /* potentially expensive */ }
  else { /* default */ }

Why it matters:

  • Short-circuiting with && and || can skip unnecessary or unsafe work.
  • Ordering improves performance on common paths and prevents rare-but-costly edge cases.
  • Makes intent clearer to readers (“guard” first, “happy path” next).
